# 实验 2 人体解剖浏览器模型加载修复交付

## 1. 根因与证据

问题不是单一故障，而是四层叠加：

1. **本地页面脚本/样式被 CORS 拦截（首因）**
   - Vite 产物 `index.html` 使用 `<script type="module" crossorigin>` 和 `crossorigin` 样式链接。
   - ArkWeb 以 `resource://rawfile/` 的 opaque origin 加载页面，模块/CORS 请求被拒绝。
   - 证据：`doc/check-evidence/repro-hilog.txt`
     - `Access to CSS stylesheet at 'resource://rawfile/human-atlas/assets/...css' ... blocked by CORS policy`
     - `Access to script at 'resource://rawfile/human-atlas/assets/...js' ... blocked by CORS policy`
   - 结果：JS 未执行、`NativeBridge` 未注册、模型请求未发出、原生遮罩停留 0%。

2. **去掉 CORS 后，Fetch API 不支持 `resource://`**
   - 证据：`doc/check-evidence/fix1-hilog.txt`
     - `Fetch API cannot load resource://rawfile/human-atlas/models/atlas.json. URL scheme "resource" is not supported.`
   - 结果：JS 已执行，但 `atlas.json` 和 gzip 分块请求仍未进入本地拦截。

3. **原生加载状态判断不可靠**
   - `onPageEnd` 过早清除超时定时器，JS 失败后不会进入错误态。
   - 会话层 25 秒后把“桥接已注册但进度未满”误判为 ready，可能掩盖真实失败。
   - `runJavaScript` 实际返回带引号的 `"true"`，原逻辑按 `true` 比较，导致搜索虽命中但被判定为 not-found。
   - 证据：`fix4-search3-hilog.txt` 中 `locate result: heart raw="true"`，随后无 found；修复后 `final-interaction-hilog.txt` 中 `raw=true`。

4. **ArkWeb/WebGL 首帧与截屏表现**
   - WebGL2 上下文正常（Mali-G77，无 GL 错误），模型分块和进度 100% 均正常。
   - 但首帧在画布尺寸稳定前绘制，初始化后画面只剩清屏色；系统 `snapshot_display` 也不捕获 WebGL 图层。
   - 修复：bundle 开启 `preserveDrawingBuffer`，页面侧在模型加载后延迟切换一次默认系统以触发无副作用重绘。
   - 证据：`acceptance-model-visible.png`（设备内 Web 调试截图，人体模型清晰可见）。

## 2. 修改文件与内容

- `entry/src/main/resources/rawfile/human-atlas/index.html`
  - 去掉 `type="module"` 与 `crossorigin`。
  - 增加资源/脚本错误上报 `NativeBridge.onWebError`。
  - 增加 `__atlasProgress`、`__atlasCanvasInfo` 诊断探针。
  - 增加模型加载后延迟重绘逻辑，解决 ArkWeb 首帧空白。

- `entry/src/main/ets/bridge/AtlasResources.ts`
  - 新增 `ATLAS_ORIGIN` / `ATLAS_PAGE_URL`，使用 `https://www.example.com/human-atlas/index.html` 假域名加载本地页。
  - 新增 `isAtlasRequest()`，只拦截 Atlas 自身资源；外链、`data:`、`about:` 等交还 Web 自己处理。
  - `mapRawfilePath()` 同时兼容假域名、历史 `resource://rawfile`、相对路径与 `/models/*` 根路径分块。

- `entry/src/main/ets/pages/AnatomyBrowser.ets`
  - Web 源从 `$rawfile(...)` 改为假域名入口。
  - `onInterceptRequest` 读取 rawfile 返回二进制，缺失资源返回明确 404，并记录路径日志。
  - 加载超时改为“进度停滞 90 秒”且只在真实 ready 时解除；错误提示附带阶段诊断。
  - 进度变化重新计时；`onPageEnd` 不再提前清除计时器。

- `entry/src/main/ets/bridge/AnatomySession.ets`
  - 移除 25 秒假就绪兜底；ready 必须由 Web 加载 + 桥接注册 + 进度 100% 共同驱动。
  - 解包 `runJavaScript` 返回的 `"true"`/`"1"`，修复搜索误判与 reprobe。
  - `reprobe()` 现在检查真实进度探针，不再仅凭桥接对象存在就判定 ready。
  - 增加阶段诊断字符串与 `AnatomyBrowser` hilog 日志。

- `entry/src/main/resources/rawfile/human-atlas/assets/index-1ie-Jbum.js`
  - 最小补丁：WebGLRenderer 参数增加 `preserveDrawingBuffer: true`，`powerPreference` 改为 `default`。
  - 注意：该文件是 Vite 压缩产物；若将来从前端源码重新构建，需要重新应用此补丁。

- `tests/anatomy-browser.test.cjs`
  - 新增假域名映射、非 Atlas 请求不拦截、HTML 不使用 module/crossorigin、首帧重绘、进度未满不 ready、`"true"` 解包等回归用例。
